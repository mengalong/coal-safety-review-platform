# 生产容量验收方案

## 1. 目标与边界

容量验收覆盖登录后任务查询、并发建任务、大文件上传、解析队列积压与恢复。测试只在隔离的候选环境执行，
使用独立管理员测试账户和 `LOAD-` 产品型号前缀，不得对正式审核数据直接施压。

## 2. 工具

密码通过 `COAL_LOAD_TEST_PASSWORD` 注入，不进入命令参数和输出：

```bash
export COAL_LOAD_TEST_PASSWORD='由密钥管理系统注入'
scripts/load-test.sh --base-url https://coal-review.example.com:8443 \
  --login-name load-test-admin --mode mixed --requests 300 --concurrency 20 \
  --file-size-mb 20 --confirm-write --max-error-rate 0.01 --max-p95-ms 5000 \
  --wait-queue-seconds 1800 \
  --output artifacts/load-test-mixed.json
```

企业内部 CA 使用 `--ca-file /secure/ca/enterprise-ca.pem`，工具不提供关闭 TLS 验证的选项。

`read` 模式不写数据；`tasks`、`uploads`、`mixed` 必须显式指定 `--confirm-write`。上传大小限制为 1 至
49 MiB，与平台 50 MiB 单文件解析上限保留 multipart 余量。工具并发执行请求，同时每 500ms 采样管理端作业列表，输出请求量、
吞吐、错误率、P50/P95/P99/最大延迟、操作分布和等待队列峰值，未达到门槛时退出码为 1。

## 3. 验收矩阵

| 场景 | 建议参数 | 默认通过门槛 |
|---|---|---|
| 查询基线 | 500 请求，并发 20 | 错误率不高于 1%，P95 不高于 2 秒 |
| 混合业务 | 300 单元，并发 20，20 MiB | 错误率不高于 1%，P95 不高于 5 秒 |
| 大文件 | 50 单元，并发 5，49 MiB | 错误率不高于 1%，P95 不高于 30 秒 |
| 队列恢复 | 100 个上传，并发 20 | 停止加压后 30 分钟内等待队列归零且无丢失作业 |

目标环境应按实际 CPU、内存、磁盘和外部模型配额调整并发，但调整后的签署门槛必须在测试前确定。
每次结果 JSON 与候选 Commit、容器镜像摘要、主机规格、Worker 并发和模型限流配置一同归档。

## 4. 当前交付环境结果

2026-07-29 使用完整容器栈完成以下基线验收。该结果证明工具链和应用队列行为满足当前环境门槛，目标主机仍须
按签署参数重跑建议矩阵：

| 场景 | 实际参数 | 结果 |
|---|---|---|
| 查询基线 | 200 请求，并发 20 | 错误率 0，约 95.9 RPS，P95 约 562 ms |
| 混合业务 | 60 单元，并发 20，1 MiB 文件 | 80 个实际请求，错误率 0，P95 1568.31 ms，队列峰值 2 并成功排空 |
| 大文件 | 2 单元，并发 2，20 MiB 文件 | 4 个实际请求，错误率 0，P95 770.44 ms，队列峰值 2，1.055 秒排空 |

混合测试同时验证 PostgreSQL 年度任务编号并发分配不会产生唯一键冲突。确定性文档解析错误不再由 Worker
重复调度，网络和基础设施类异常仍保留有限重试。

## 5. 执行后检查

1. 核对创建任务数、上传文件数与队列作业数，不接受静默丢失。
2. 核对失败作业均有可诊断错误，重试不会越过终态保护。
3. 观察 PostgreSQL、Redis、MinIO、API、Worker 指标和容器资源峰值。
4. 随机抽查解析证据坐标、中文报告和人工确认流程。
5. 清理 `LOAD-` 测试任务前保留验收记录，不清理任何非测试数据。
