# 生产部署与运维手册

## 1. 交付拓扑

生产环境使用 `compose.production.yaml`，由 HTTPS Nginx、FastAPI、Celery Worker、PostgreSQL/pgvector、
Redis 和 MinIO 组成。仅 Web 服务暴露宿主机端口，应用网和数据网均为内部网络。API 和 Worker 额外连接
不发布端口的 `model-egress` 网络访问外部模型，PostgreSQL、Redis 和 MinIO 不连接该网络。API、Worker
和 Web 容器启用只读根文件系统、临时目录、能力删除及 `no-new-privileges`。

生产环境不得启用演示数据、SQLite 或本地对象存储。一个任务仍只对应一个产品型号；标准、规则、
执行器元数据及其版本快照的业务边界不因部署方式改变。

## 2. 首次部署

1. 从 `.env.production.example` 创建部署主机上的 `.env.production`，权限设置为 `600`。
2. 通过密钥管理系统注入数据库、Redis、MinIO、JWT、模型加密主密钥和千帆 API Key。
3. 安装可信 TLS 证书，将证书和私钥路径写入环境文件。私钥权限不得高于 `600`。
4. 运行 `scripts/security-baseline-check.sh .env.production`。
5. 构建并推送 API 和 Web 镜像，将 `COAL_RELEASE_COMMIT` 设置为完整 40 位候选 Commit，并将
   `COAL_API_IMAGE`、`COAL_WEB_IMAGE` 固定为仓库 `sha256` 摘要。
6. 运行 `docker compose --env-file .env.production -f compose.production.yaml up -d --no-build`。
7. 运行 `scripts/production-smoke-test.sh .env.production`。
8. 创建首个管理员：

   ```bash
   docker compose --env-file .env.production -f compose.production.yaml run --rm \
     -e COAL_BOOTSTRAP_ADMIN_PASSWORD api python -m coal_platform.cli bootstrap-admin \
     --login-name admin --display-name 系统管理员
   ```

引导命令要求至少 12 位密码，数据库已有管理员时会拒绝再次执行。首次登录后应立即修改密码并撤销
引导阶段的临时凭据。

需要生产观测栈时增加 `--profile observability`。`COAL_METRICS_TOKEN_FILE` 的文件内容必须与
`COAL_METRICS_TOKEN` 完全一致；Grafana 默认仅绑定 `127.0.0.1:3000`，应通过运维 VPN、SSH 隧道或
受控反向代理访问，禁止直接暴露公网。

## 3. 日常检查

- `/api/v1/healthz` 仅表示 API 进程存活；`/api/v1/readyz` 同时检查数据存储可用性。
- `scripts/production-smoke-test.sh` 默认等待容器健康状态收敛 120 秒，再检查 HTTPS 安全头、PostgreSQL、
  Redis、Celery 和 MinIO；`unhealthy`、退出或重启状态会立即失败。慢启动环境可预先设置
  `COAL_SMOKE_WAIT_SECONDS`，但不得跳过健康检查。
- 管理端监控页检查队列等待、运行、失败数量、Worker 在线状态及系统告警。
- 日志中使用 `X-Trace-Id` 串联请求，不得记录登录令牌、模型 API Key、文档原文或完整证据内容。

Prometheus 每 15 秒使用独立 Bearer Token 拉取 `/api/v1/metrics`，指标包含 HTTP 请求与延迟、队列状态、
最近 500 次模型调用失败率、数据库、Redis 和 Worker 可用性。告警覆盖 API、数据库、Worker、队列积压、
模型失败率和 API 5xx；Alertmanager 将最小化后的告警字段交给通知转发服务，再使用
`COAL_ALERT_WEBHOOK_URL` 和可选 Bearer Token 投递到企业通知平台。

应用输出单行 JSON 日志。Promtail 只读采集专用部署主机的 Docker JSON 日志并写入 Loki，Grafana 自动
配置 Prometheus 与 Loki 数据源。若目标环境使用 Kubernetes 或集中日志代理，应停用 Promtail，直接采集
容器标准输出。日志采集权限只能授予专用部署节点，不得跨宿主机读取无关容器日志。

## 4. 迁移与备份恢复

发布前运行 `scripts/migration-drill.sh`，脚本会在隔离数据库执行 `upgrade -> downgrade -> upgrade`，
不会操作生产数据库。正式迁移由 API 容器启动命令在服务接流量前执行。

运行 `scripts/backup.sh .env.production /secure/coal-backups` 同时备份 PostgreSQL 和 MinIO，并生成
SHA-256 清单。生产环境必须配置 `COAL_BACKUP_AGE_RECIPIENT` 或将备份目录置于加密卷。模型加密主密钥
不得进入数据库备份，必须由独立密钥管理系统托管和备份。

恢复是破坏性操作，仅在维护窗口执行：

```bash
scripts/restore.sh --confirm /secure/coal-backups/20260729T000000Z .env.production
```

加密备份恢复时传入 `.tar.gz.age` 文件，并通过 `COAL_BACKUP_AGE_IDENTITY_FILE` 注入独立保存的 age 身份文件。

恢复前保留当前快照；恢复后执行冒烟测试和关键报告抽检。目标 RPO 为 24 小时，目标 RTO 为 4 小时，
每季度至少完成一次恢复演练并记录实际耗时。

## 5. 对象生命周期

`scripts/configure-minio-lifecycle.sh` 开启 `coal-review` 桶版本控制，清理 `tmp/` 前缀下超过 7 天的
临时对象，并清理超过 30 天的非当前版本。正式报告、原始上传件和审核证据不配置自动到期；其保留期
由项目归档制度控制。

## 6. 密钥与安全

- JWT 密钥、模型加密主密钥、千帆 API Key、数据库及存储凭据分别生成和轮换。
- JWT 密钥轮换会使现有会话失效，应提前发布维护通知。
- 模型密钥使用平台轮换接口更新；接口只返回掩码，不回显明文。
- TLS 证书到期前 30 天更换，基线脚本会拒绝 7 天内到期的证书。
- 每次发布检查 CORS 只包含正式 HTTPS 域名，且生产配置校验必须通过。
- 在主机防火墙或企业出口代理中，将 `model-egress` 仅放行千帆 API 域名和 HTTPS 443。
- 备份、日志、错误响应及工单中均不得复制任何明文密钥。

## 7. 故障与回退

队列积压时先暂停新增审核，确认 Worker、Redis 和外部模型状态，再扩充 Worker 并发。外部模型熔断时
保留作业和审核状态，待服务恢复后从管理端重试，禁止绕过证据充分性和人工最终确认。

应用回退必须使用已验证的前一版本镜像；涉及不可向后兼容的数据迁移时，先停 Web/API/Worker，再用
已验证备份恢复数据库和对象存储，最后启动前一版本并执行冒烟测试。不得仅回退代码而忽略数据库版本。

候选发布前由密钥管理系统注入 `COAL_UAT_PASSWORD`。`COAL_UAT_MODE` 默认为 `basic`；正式签署候选可设为
`full`，并同时显式设置 `COAL_UAT_CONFIRM_MODEL_COST=true`。候选发布执行
`scripts/release.sh --confirm .env.production /secure/coal-backups`。脚本拒绝非摘要镜像，依次执行安全基线、镜像
拉取、迁移升降级演练、联合备份、正式迁移、启动、冒烟和 UAT 门禁，并输出权限为 `600` 的发布记录。
记录包含成功或失败状态、耗时、镜像摘要、备份路径和 UAT JSON 证据。发布前必须保留上一版本的环境文件，
其中 Commit 和镜像摘要不可被覆盖。发布脚本拒绝缺失或缩写的 `COAL_RELEASE_COMMIT`，发布记录通过
`candidate_commit` 将 UAT、备份和镜像绑定到代码版本。

回退执行：

```bash
export COAL_BACKUP_AGE_IDENTITY_FILE=/secure/age/coal-backup-identity.txt
scripts/rollback.sh --confirm .env.previous /secure/coal-backups/20260729T000000Z.tar.gz.age .env.production
```

脚本先停止当前 Web/API/Worker，拉取上一版本摘要镜像，恢复数据库与对象，再启动上一版本并完成冒烟和 UAT
门禁。正式模式要求当前和上一环境均包含完整 Commit 及不可变 API/Web 镜像摘要；记录保存候选与上一 Commit、
两组镜像、备份和 UAT。成功或失败记录写入备份根目录的 `release-records/*-rollback.env`，不得只回退数据库
或只覆盖对象存储。

隔离测试环境可在第五个参数传入 `--local-drill`，使用已在本机构建的上一 Commit 镜像执行同样的停止、整体恢复、
启动、冒烟和 UAT，仅跳过远程镜像拉取。记录会写明 `image_pull=skipped-local-drill`，不能用于生产签署；正式回退
必须省略该参数并拉取上一版本不可变摘要。

正式 UAT 和回退通过后，从 `deploy/production-signoff.example.json` 形成目标环境签署清单。将发布记录、发布 UAT、
回退记录和回退 UAT 的 SHA-256 填入清单，并由业务与运维代表分别填写姓名、角色、`approved` 决策和带时区签署时间：

```bash
shasum -a 256 release.env release-uat.json rollback.env rollback-uat.json
scripts/verify-production-signoff.sh \
  --release-record release.env \
  --rollback-record rollback.env \
  --signoff production-signoff.json \
  --output production-signoff-result.json
```

验证器要求发布和回退均使用完整 UAT、正式回退拉取不可变摘要、回退恢复发布前同一备份、候选与上一版本不同、
阻断和高等级缺陷为零且双签署批准。输出 `status=passed` 后才可归档为最终生产签署证据；原始四份证据、签署清单
和验证结果必须作为同一归档单元保存。
