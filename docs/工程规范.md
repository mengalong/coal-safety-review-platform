# 工程规范

## 代码与命名

- Python 使用 Ruff 校验，目标版本为 Python 3.11，单行长度不超过 120 个字符。
- 模块、函数和变量使用 `snake_case`，类使用 `PascalCase`，常量使用大写下划线。
- API 路径使用复数资源名；状态变化使用明确的动作后缀，例如 `/publish`、`/retry`。
- Store 协议、DemoStore 和 SQLAlchemyStore 必须保持同一业务契约。
- 版本快照、报告内容快照和执行输入快照创建后不可回写。

## 日志与审计

- 请求通过 `X-Trace-Id` 关联日志；未提供时由 API 自动生成。
- 修改标准、规则、文件、问题、配置和报告时必须写入 `operation_log`。
- 日志记录操作人、实体、动作、前后快照、原因和 trace id。
- API Key、密码和访问令牌不得写入日志或响应；敏感配置只返回是否已配置。
- Worker 异常必须包含稳定错误码、可读消息和作业编号。

## 测试与提交

- 提交前运行 `conda run -n coal pytest -q`、`ruff check coal_platform tests` 和 `git diff --check`。
- 数据库 Store 的新增能力必须至少有一个 SQLite 持久化测试或明确说明原因。
- Commit 使用中文标题，并以条目列出改动概述；一个提交对应一个完整开发单元。
- 主分支提交前必须通过测试，文档清单与实现状态保持同步。
