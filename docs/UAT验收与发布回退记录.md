# UAT 验收与发布回退记录

## 1. 自动化 UAT

使用专用管理员账户，密码只从 `COAL_UAT_PASSWORD` 读取。基础模式创建带 `UAT-` 型号的独立任务，验证登录
会话、一个任务一个产品型号、初始轮次、资料上传、异步解析、证据块追溯和人工解析确认：

```bash
export COAL_UAT_PASSWORD='由密钥管理系统注入'
scripts/uat.sh --base-url https://coal-review.example.com:8443 \
  --login-name uat-admin --confirm-write --output artifacts/uat-basic.json
```

完整模式会调用已配置的外部模型，因此额外要求显式确认费用。它使用目标环境已有的活动标准版本，继续验证
标准确认、动态原子项、三层规则装配、版本快照、真实审核、证据问题人工确认、确认式局部重跑、标准覆盖检查、
报告发布和 Word/PDF 下载：

```bash
scripts/uat.sh --base-url https://coal-review.example.com:8443 \
  --login-name uat-admin --confirm-write --full-audit --confirm-model-cost \
  --output artifacts/uat-full.json
```

企业内部 CA 通过 `--ca-file` 指定。工具不提供跳过 TLS 验证的参数。目标环境至少需要一个含已发布解析修订的
活动标准版本、可装配的活动规则/执行器版本、可用的千帆模型配置及在线 Worker，否则完整 UAT 明确失败。

## 2. 人工验收

自动化通过后，业务代表仍须在前端逐项确认：

- 审核人员只能看到本人任务，管理员可完成目录与运行管理。
- 任务、轮次、文件、标准覆盖和问题证据在桌面与移动宽度下无重叠或截断。
- 扫描 PDF 页缩略图、区域证据、Word 表格行和 Excel 单元格范围可回到原资料。
- 动态项不适用和转人工决策均要求理由，未确认项阻止报告发布。
- 模型不确定或证据不足时不输出确定合格结论。
- 局部重跑弹出确认范围，不覆盖无关规则执行和人工结论。
- 报告 Word/PDF 中文、页码、表格、长文本和打印效果符合交付样张。
- 模型密钥、指标令牌、用户令牌在页面、API、日志和错误信息中均不回显。

## 3. 缺陷收敛

缺陷按 `阻断上线 / 高 / 中 / 低` 记录，必须包含候选 Commit、复现步骤、trace ID、预期与实际结果、修复提交
和回归证据。上线门槛为：阻断上线和高等级缺陷为零；中等级缺陷均有业务与运维共同接受的处置计划；所有修复
重新通过后端、前端、Compose、安全基线、基础 UAT 和受影响专项测试。

## 4. 发布与回退演练

发布使用固定镜像摘要和 `scripts/release.sh`。演练至少记录：迁移演练耗时、联合备份路径与校验、发布耗时、
冒烟结果、完整 UAT 结果。随后使用上一版本环境文件和本次发布前备份执行 `scripts/rollback.sh`，再次运行冒烟
与基础 UAT，确认任务、对象、会话和报告可读取。演练结束后可重新发布候选版本。
