# 第二期生产交付任务清单

## 1. 目标

在不改变第一期主设计原则的前提下，将已完成的功能闭环提升为可部署、可运维、可验收的生产系统。第二期以真实文档处理、真实模型调用、生产前端和端到端交付验证为主线。

## 2. 账户安全与作业控制

- [x] 用户修改密码
- [x] 修改密码后撤销用户全部有效会话
- [x] 待执行作业取消与终态保护
- [x] 密码修改和作业取消操作审计

验收：用户修改密码后所有旧令牌立即失效；管理员只能取消尚未执行的作业，已取消作业不能运行或重试。

## 3. 真实文档处理

- [x] PDF、Word 和 Excel 文本解析
- [x] 扫描件 OCR 与版面坐标保留
- [x] Word 表格行、Excel 工作表和单元格范围证据定位
- [x] 图纸页识别、缩略图和区域证据定位
- [x] 解析失败重试、质量指标和人工修订闭环

验收：上传的技术资料能生成可追溯到页码、区域或单元格的结构化证据。

## 4. 模型接入与智能审核

- [x] 模型密钥可逆加密存储和轮换
- [x] 文本模型与多模态模型统一客户端
- [x] 超时、限流、重试、熔断和调用审计
- [x] 动态原子审核项的真实模型执行
- [x] 证据充分性判定和不可确定结果约束

验收：在不依赖 GPU 的部署环境中，可以通过外部模型完成带证据的审核，模型失败不会破坏任务状态。

## 5. React 生产前端

- [x] 登录、修改密码和会话失效处理
- [x] 任务、文件、轮次和审核工作台
- [x] 标准、规则、执行器和规则包管理
- [x] 问题复核、证据查看和确认式局部重跑
- [x] 报告预览下载、系统配置和运行监控

验收：审核人员和管理员可在生产前端完成各自的核心业务闭环，无需调用 API 或原型页面。

交付记录：`frontend/` 提供 Vite/React/TypeScript 生产前端，覆盖审核人员与管理员路由、真实 API
访问、401 会话失效、密钥不回显和移动端导航。前端通过 TypeScript 生产构建、ESLint 和 8 项组件测试；
Nginx 镜像提供同源 API 代理、SPA 路由回退、上传限制、健康检查和基础安全响应头。

## 6. 生产部署与验收

- [x] PostgreSQL、Redis、Celery、MinIO 全链路容器验收
- [x] 数据迁移、备份恢复和对象存储生命周期方案
- [x] HTTPS、密钥注入、最小权限和安全基线检查
- [x] 并发审核、队列积压和大文件压力测试
- [x] 中文 Word/PDF 排版和打印质量验收
- [x] 监控指标、日志采集、告警通知和运维手册
- [x] 自动化基础 UAT、缺陷收敛工具和生产发布回退流程
- [x] 隔离环境上一 Commit 镜像、数据库和对象存储整体回退机械演练
- [ ] 目标环境完整真实模型 UAT、不可变摘要回退和业务/运维签署

验收：目标部署环境完成安装、迁移、压测、安全检查、业务验收和回退演练，并形成可签署的交付记录。

交付记录：生产 Compose 隔离 Web、应用与数据网络，通过环境变量强制注入密钥，并启用 HTTPS、安全响应头、
只读容器和最小能力；生产配置启动时拒绝演示数据、SQLite、本地存储、弱密钥和本地 CORS。已交付迁移演练、
数据库与对象联合备份恢复、MinIO 生命周期、安全基线和冒烟脚本，以及首管理员一次性引导命令。中文 Word/PDF
报告通过 A4、嵌入字体、表格、长文本换行和四页分页目视验收。目标环境实跑状态单独记录在
`docs/生产验收记录.md`，未实跑项目不得据此签署上线。

外部模型访问通过 API/Worker 专用 `model-egress` 网络提供；应用与数据网络继续保持 `internal`，数据库、Redis
和 MinIO 不连接出站网络。生产主机应在出口防火墙或代理侧仅放行千帆 HTTPS 域名。

可观测性交付记录：API 输出脱敏 JSON 访问日志并提供独立 Token 保护的 Prometheus 指标，实时呈现请求延迟、
队列状态、模型失败率以及数据库、Redis、Worker 可用性。生产观测 profile 包含 Prometheus、Alertmanager、
Loki、Promtail 和 Grafana，并由通知转发服务将最小化告警投递到企业 Webhook。压力测试工具及验收矩阵见
`docs/生产容量验收方案.md`；目标环境结果产生前，压力测试条目保持未完成。

发布验收工具记录：生产服务支持 API/Web 固定镜像摘要；发布脚本串联安全基线、迁移升降级演练、联合备份、
正式迁移、服务切换、冒烟测试和强制 UAT，回退脚本使用上一版本摘要及数据库/对象备份整体恢复，并再次执行
冒烟和 UAT。成功或失败均归档耗时、镜像、备份及 UAT 证据。UAT 工具分基础和真实模型完整审核两种模式，
输出机器可读签署证据。完整模式强制验证文本、多模态、向量和重排序四个指定生产模型的真实请求及成功审计，
再执行动态审核证据闭环。执行与缺陷收敛口径见 `docs/UAT验收与发布回退记录.md`；在目标环境完成完整 UAT
和实际回退前，对应清单条目保持未完成。

最终签署门禁通过 `COAL_RELEASE_COMMIT`、API/Web 不可变摘要和 SHA-256 将发布记录、发布完整 UAT、正式回退
记录、回退完整 UAT 与双签署清单绑定。`scripts/verify-production-signoff.sh` 同时校验正式摘要拉取、同一备份点、
候选与上一版本、零阻断/高等级缺陷以及业务和运维 `approved` 决策；只有验证结果为 `passed` 才能勾选最终条目。

2026-07-29 回退演练补充记录：使用 Commit `cf2a72a` 预构建的上一版本 API/Web 镜像和联合备份执行
